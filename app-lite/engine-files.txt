# Engine sources staged into the serverless (shinylive / webR) build, one filename
# per line, resolved against r/pilotr/R. Blank lines and #-comments are ignored.
#
# This is the ONE place the browser build's engine subset is named. app.R loads
# whatever was staged beside it, and both staging paths, build_shinylive.R and
# .github/workflows/site.yml, read this file. Lists kept in step by hand in each of
# them would drift, and a subset without validate.R, which defines the
# .required_spec_version() that build_spec() calls and the validate_spec() that
# simulate_design() calls, would ship an app whose every Simulate click fails.
#
# The browser build deliberately carries a subset, not all of R/: app.R calls no
# function defined in the rest of it, which includes mixed-effects power, the
# Bayesian design analysis, the brms bridge, the sweeps, the precision analysis
# and the reports. Crossed mixed-effects power is left to the installed package.
#
# solve_curve.R is in the subset because the app draws a power curve against a
# target line, and reporting where the curve meets it is the point of drawing it.
# The file needs nothing beyond base R and core.R.
#
# mcse.R is in the subset because power_design() in power.R reports each rate with
# its Monte Carlo error, which mcse.R computes. It needs nothing beyond base R.
#
# autoformula.R is in the subset because validate_spec() in validate.R names the
# analysis column of each interaction with the .us() that autoformula.R defines. It
# needs nothing beyond base R, stats and the other files listed here.
core.R
simulate.R
parallel.R
power.R
mcse.R
solve_curve.R
validate.R
